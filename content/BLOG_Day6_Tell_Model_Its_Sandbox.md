# 我关掉了网络，却忘了告诉 Agent

> 日期：2026-09-15
> 项目：agent-lite，一个我用 Python 练习做的编程助手

前几天，我给助手运行命令的环境加了一道保护：只能改当前项目，看不到 Windows 上的其他磁盘，也不能联网。安全边界清楚了，我以为这件事就算做完了。

实际使用时，助手却开始到处碰壁。它先找项目文件，再去找宿主机目录，接着寻找 Node、npm 和 Python；缺了依赖，又反复尝试安装。没有网络，下载当然不会成功。它换着命令试了很多次，最后把调用次数用完，任务还是没完成。

它不是故意忽略限制，而是从来没有人把这些限制告诉它。

## 我知道，程序也知道，只有它不知道

排查时我发现，程序里早有一段环境说明，写着“不能联网、只有项目目录可写”。可这段话只在启动时打印到我的屏幕上。模型收到的工具说明里没有它。

换句话说，我为助手搭了一间有规则的房间，却没有把房间的规则交给助手。它只能靠一次次失败去摸索哪里有门、哪里是墙。

我原本想在启动时先探测完整环境，再把结果告诉它。但为了让界面尽快出现，我此前把环境探测推迟到了第一次执行命令。等探测完再说明，第一次命令已经可能走错。所以最基本的规则必须在启动沙箱之前就能写出来。

## 把规则放到它每次都会看的地方

我把环境说明加进命令工具本身的说明里。除了说“没有网络、只允许修改当前项目”，还写清楚遇到这些限制该怎么做：需要某个运行环境时只检查一次；确实没有，就说明缺什么；不要反复搜宿主机目录，也不要在无网络环境里一遍遍尝试下载。

这样做并不能保证模型从此每次都判断正确，但至少它在第一次使用命令之前，就已经拿到了必要的信息。我加了测试，确认不启动沙箱也能取得这段说明，且关键限制没有漏掉。

顺着这次排查，我还修了两个会妨碍使用的小问题：运行的子命令不再抢占我正在输入的终端；WSL 在命令输出前插入的系统警告也会单独处理，避免和正文混在一起变成乱码。

这件事让我意识到：程序“知道”某个限制，不代表助手“知道”。想让它在受限环境里做出合理选择，就得在它准备行动的地方，把规则说成具体可执行的话。

# 让我的小 Agent 不再只是一次性脚本

> 日期：2026-08-20
> 项目：agent-lite，一个我用 Python 练习做的编程助手

最开始，这个项目只有大约 150 行代码。把问题交给它，它调用模型、执行命令，再把结果打印到终端。作为演示，它已经能跑；可一旦我想让它多做一点事，问题就冒出来了：工具失败和正常输出都是一段文字，界面显示和处理逻辑混在一起，命令卡住时，整个助手也可能跟着等下去。

我想做的不是再加一个功能按钮，而是让这个小助手有一个能长期使用的“底座”。以后无论换成网页界面，还是继续用终端，都不用重写它如何思考、调用工具和结束任务。

## 先让它看得懂工具的结果

以前工具只返回字符串。命令失败时，如果没有明确标记，助手很难分清“这是命令正常打印的一句话”，还是“这次操作没有成功”。我把结果改成同时包含内容和是否出错的信息，所有工具抛出的异常也集中在同一个地方处理。

这看起来只是换了返回格式，却直接影响助手下一步怎么做。比如参数里本该填文件路径，却误填了数字。原来的报错是一串 Python 内部类型名称，既没有说清哪个参数错了，也没有告诉它该怎么改。现在会明确说“路径应当是文字，收到的却是数字”。错误提示的目的不是显得专业，而是让下一次尝试有方向。

## 命令卡住时，至少能把控制权拿回来

我给工具加了等待上限。第一次实现看似成功：超过时间后，主流程会收到超时通知。可测试时发现它仍然没有继续，因为我用的线程管理方式在退出时还会等待那个卡住的线程。所谓“超时”，只是换了一个地方继续等。

改完之后，主流程能在期限到时停止等待并继续处理。但这里有个边界：Python 不能随意强行杀掉正在运行的线程。所以这是一道防止助手一直等待的兜底，不代表后台工作一定被立刻终止。像运行外部命令这样的工具，还需要自己给子进程设置超时。

## 把“做事”和“显示给我看”拆开

原先助手每走一步都直接打印。这样终端能看见过程，但别的界面很难复用。我把打印改成了一连串事件：开始思考、调用工具、得到结果、完成任务。终端负责把事件显示出来，助手核心只负责做事。

我也把“一直运行到结束”拆成了可以单独执行的一步，并让外部能够查看它当前是在等待、思考，还是调用工具。现在按下中止键时，它会在合适的位置结束当前任务，而不是粗暴地关掉整个程序。

这次最让我在意的不是代码从 150 行变成了多少行，而是三个很实际的变化：出错时说得清楚，卡住时能继续，界面不再和核心逻辑绑死。这个底座并不意味着助手已经足够可靠；后面真正使用时，我还会遇到编码、对话长度和取消操作的问题。至少从今天起，碰到这些问题时，我有了一个能逐步修补的地方。
